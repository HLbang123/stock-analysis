用户（2026-08-11）明确要求：UI 里大量解释性文本（用了什么模型、什么口径、什么算法）是噪音，"用户根本不在乎这些，解释只会让页面很乱"。当日已全站清理一轮（删+缩短约 40 处）。

**Why:** 面向非技术用户，技术细节不帮助决策，只稀释关键信息。

**How to apply:** 写 UI 文案时：
- 禁提实现细节：模型名（DeepSeek/LLM/GLM）、API、token、数据源名（同花顺/Tushare/腾讯）、统计术语（Spearman/IC/校准/回填/落库）、内部代号（P2/P3）、运维指令（run-daily 等脚本名）
- 卡片副标题/图注超过一句就砍；tooltip 一句话以内
- 空态只留一句引导，不写教程（"勾选条件，点击查询"足矣）
- 功能性提示保留（非交易时段、断点续跑）；规则说明类放默认折叠区可以保留
- 免责声明"信号参考，非操作指令"全站保留一处即可（TScorePanel 主结果页）
- **更新日志只写用户看得见的功能/修复**（2026-08-11 用户明确）：删掉"LLM 重排改流式""请求层收敛""自动落库"这类纯技术条目；同样禁模型名/数据源名/内部规则编号（R01 等）/"股"字。修复类写用户视角的症状（"修复资金流显示为 0"），不写根因（"字段错位"）。鸣谢 drawer 不受此限
- **更新日志一条一句、不写使用说明**（2026-08-12 用户明确）：只写"是什么"，不写"怎么用/有什么细节"。反例："清单：可查看最近同步时间，点名称重命名、或移除设备，改动自动同步"→ 正例："可查看已连接设备，支持改名与移除"。交互细节让用户自己发现
- 合规约束同样适用：对外文案禁"股"字，见 [[naming-compliance]]
